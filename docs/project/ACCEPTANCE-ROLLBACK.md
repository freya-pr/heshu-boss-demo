# 验收与回滚小结

## 本迭代完成标准

1. 双击 `启动SCRM演示版.command`（兼容保留的脚本名）后，60 秒内自动打开合数BOSS：`http://127.0.0.1:5173`。
2. `admin / Scrm@2026` 可登录，工作台、线索、客户和系统管理菜单切换后内容正确变化；业务提醒从顶部通知入口查看，不生成消息中心菜单。
3. 待分配线索可分配员工活码，已分配线索可确认加微，已加微线索可转为客户。
4. 手机号或 UnionID 任一有效可建客；每个有效客户只能保存一个全局唯一的主手机号，不出现备用手机号或多手机号数组；重复手机号复用已有客户，手机号与UnionID分别命中不同客户时必须阻断自动建档、自动生成撞单案件，并可在 V1.0 撞单管理完成领取、证据核验、指定主档合并或确认不同人，完整保留审计记录。
5. 演示模式与正式后端模式在 UI 明确标记，Stub 不得伪装为真实外部接口。
6. 前端 `vue-tsc --noEmit` 与 `vite build` 通过；正式交付前后端 `mvn test` 与 Docker 端到端验收必须通过。
7. 系统参数支持类型校验、敏感值掩码和版本记录；字典类型与字典项支持主从维护、启停和历史值兼容。
8. IP列表在“IP大类”同一单元格中展示大类名称，并在名称下方展示“大类编码”；支持按IP大类名称或编码筛选。IP大类读取 `ip_category` 字典，字典项值作为大类编码，初始项为“教育规划/EDUCATION_PLANNING”，示例老师IP为“阿留皮皮”。
9. IP列表展示IP渠道名称及稳定渠道编号，初始渠道为“店播/CH000001”“阿留专属/CH000002”，并支持筛选与编辑。
10. IP编号显示在IP名称下方，大类编码显示在IP大类下方；IP配置可集中维护IP名称—IP大类—IP渠道关系且不产生重复主档。
11. 活码新建和编辑支持搜索关联IP；选中后自动带出只读IP渠道，保存后列表、详情和历史关系中的IP编号与渠道编号一致。
10. 线索中心存在独立商品列表；IP关联商品可下钻，商品列表可筛选、同步、导出和修改内部备注，长商品ID不丢位。
11. 组织员工初始化只读取整改后的企业微信通讯录；飞书数据在初始化暂存表、正式员工表、身份映射表和同步任务中均为零条。
12. 一个生效的合数BOSS登录账号最多绑定一个 `CorpID + UserID`，一个 `CorpID + UserID` 也只能绑定一个账号；重复绑定必须被服务端和数据库同时拒绝。
13. 企微换绑必须先解除旧关系并写入历史记录，再建立新关系；历史身份不能登录、获取权限或承接新增业务数据。
14. 员工管理支持在主控开启时创建并邀请企微成员，且覆盖已有成员绑定、身份冲突、邀请失败重试、待激活和激活成功；重复点击不能创建重复成员。
15. 左侧菜单、后端菜单接口和直接路由均不提供订单中心、离职继承和班级管理；订单事实仍可被线索归因和分析口径读取。
16. 引流线索页及工作台不展示“新增线索”；批量操作只保留分配、同步订单、短信群发、导入解密数据和导出非解密数据；同步订单可多选平台并按勾选顺序创建独立任务；单条操作不展示语音提醒。
17. 客户中心不展示“跟进记录”和“等级管理”二级菜单；新客户首次建档继承线索 S/A/B/C 等级，建档后可从客户列表独立编辑并完整留痕，且不反向覆盖线索等级。
17. “导入解密数据”可下载固定模板，模板必须包含订单编号和手机号；导入只按订单编号唯一命中既有引流线索并覆盖手机号，不创建线索、不改负责人/来源/订单/客户等其他字段。未命中、多命中、文件内重复和手机号格式错误均返回明确失败原因。
18. “导出非解密数据”使用当前筛选和数据权限快照，只导出解密状态为未解密且订单编号不为空的记录；文件中的手机号保持掩码，并可与页面符合条件数量核对。
19. 引流线索列表不展示线索编号；订单编号是第一业务列并固定左侧，线索来源和操作同时固定，表格设置不可隐藏订单编号；搜索、详情标题、旅程标题、等级调整和导出文件均不出现线索编号。
20. 首页“线索概览”增加营期经营报表条、IP渠道分析和商品分析；店铺、IP渠道、IP名称等全局筛选对所有汇总区同时生效。
21. 漏斗阶段、关键数量指标、IP渠道和商品行均可下钻到带筛选快照的线索/订单明细，汇总值、明细条数与导出条数可核对。
22. “导出本期报表”包含经营概览、IP渠道分析和商品分析三个数据区，并记录筛选条件、口径版本、生成时间与权限范围；IP渠道、商品和下钻明细可分别导出。
23. 经营金额统一命名为毛GMV、退款金额和净GMV，不再出现两个同名GMV；外部数据未接入显示“待接入”，分母为零显示“—”。

## V1.0 菜单与多页签迭代

### 完成标准

1. 左侧导航固定展示 V1.0 业务域，一级菜单可展开/收起，二级菜单可进入独立路由。
2. 顶部不再使用“切换系统后重生左侧菜单”的交互。
3. 连续打开不同二级菜单时，每个路由只生成一个页签，重复点击不重复创建。
4. 首页模块仅保留“线索概览”；登录、根路径及历史 `/dashboard` 地址均进入 `/leads/analytics`，该页签固定且不可关闭；其他页签可关闭。
5. 关闭非当前页签不改变当前页面；关闭当前页签后回退到左侧相邻页签。
6. 刷新页面后，当前会话的已打开页签可恢复，左侧自动展开当前业务域。

### 回滚方式

- 前端回滚 `src/config/menu.ts`、`src/stores/tabs.ts`、`src/layouts/AppLayout.vue` 和路由配置即可恢复旧导航。
- 后端回滚 `/api/v1/auth/me` 的分组菜单返回结构前，必须与前端同一版本发布，避免菜单协议不一致。

## 回滚方式

- **演示数据回滚**：在浏览器清除该本地站点数据后刷新，重新生成演示基线。
- **前端代码回滚**：按版本标签恢复 `frontend/`，重新构建并部署上一版静态产物。
- **IP/商品模块回滚**：关闭商品列表菜单权限并恢复上一版IP页面；保留已生成的渠道编号、商品同步记录和IP商品关系，不执行物理删除。
- **后端应用回滚**：保留上一版容器镜像标签，将网关流量切回上一版镜像。
- **数据库回滚**：Flyway 脚本只向前追加，不直接修改已发布脚本；数据修复使用新增补偿迁移及发布前备份。
- **企微唯一绑定回滚**：不删除绑定历史或放开唯一约束；如新版绑定流程异常，仅关闭新增/换绑入口并恢复上一版服务，保留当前有效关系，使用补偿迁移修复冲突数据后再开放。
- **企微成员开通回滚**：关闭“创建企微成员”入口并暂停新任务；不删除企微侧已创建成员或当前有效绑定，保留任务、请求号和错误记录，修复后从失败步骤继续或按对账结果补建映射。
- **业务操作回滚**：分配、客户归属和撞单等操作必须保留审计与补偿入口，不允许物理删除历史。
- **客户手机号规则回滚**：仅允许关闭主手机号补录/换号入口并恢复上一版应用，不得放开数据库唯一约束或批量回填第二手机号；已产生的换号、合并和冲突记录继续保留，通过补偿操作恢复正确主手机号。
- **解密导入回滚**：关闭导入解密数据按钮及接口开关，恢复上一版前端；已成功覆盖的数据不物理删除，由授权人员依据批次审计执行手机号字段补偿修复，并追加反向旅程与审计记录。
- **非解密导出回滚**：关闭导出按钮即可，不修改业务数据；已生成文件按敏感数据留存策略失效和清理。
- **线索概览分析回滚**：关闭IP渠道分析、商品分析及本期报表导出的前端功能开关并恢复上一版静态产物；不删除指标快照、归因关系或已生成任务，避免历史报表无法追溯。
